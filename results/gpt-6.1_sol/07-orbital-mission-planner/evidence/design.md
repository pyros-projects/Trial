# Orbit Lab design

The requested deliverable is one offline `index.html`, supporting real two-dimensional mission planning and verified browser interactions. The workspace contains no prior application. The user's end-to-end execution instruction takes precedence over interactive design approval gates.

Use Canvas 2D and native controls. A restrained navy mission-control UI has a scenario/body rail, large orbit viewport, inspector with telemetry and maneuver tools, and a transport/prediction timeline. At narrow widths, inspector and systems become accessible tabs below a full-width viewport. All icons, textures, plots and star field are drawn or embedded inline.

Physics uses pairwise Newtonian gravity with configurable Plummer softening and velocity-Verlet. Every massive body, including spacecraft with small nonzero mass, perturbs every other body. Integration uses user-selected maximum timestep with a close-encounter cap and event boundaries at scheduled burns. Prediction clones current bodies and nodes and uses the same solver; each sampled point retains the system state required to transform history and prediction into inertial, selected-body and planet–moon rotating frames. Burn components are resolved relative to the spacecraft's primary at burn time. Cartesian components remain inertial. Two-dimensional motion exposes prograde/retrograde, radial and Cartesian burns; normal burns require a 3D model and are not offered.

Telemetry uses instantaneous primary-relative osculating elements and distinguishes unbound orbits. System energy error is measured against a baseline corrected by the exact energy change of each impulse; momentum error likewise accounts for thruster impulses. Collision options are halt, merge and pass-through. Checkpoints capture all physics and maneuver state. JSON export/import and local save/load preserve missions without runtime dependencies.

Default normalized units: G=1; star mass 10000 at distance 2400, planet mass 100, moon mass 1 at radius 140, spacecraft mass 0.000001 near radius 52. Recenter the initial barycenter and momentum. Camera follows the planet by default; a system overview and off-screen markers keep the star accessible. Show live trajectories, a distinct planned trajectory after burns, orbit guides and celestial labels.

Validation: standalone file plus localhost in a clean browser restricted to local origins; desktop 1280×800 and mobile 390×844; real clicks, pointer drags and keyboard; live diagnostics only as observations. Test integration invariants with Node against the embedded core, then test scheduled maneuver execution, projected change, frame transforms, pause/step/warp/reset/checkpoint, body editing, overlays, export/import and persistence. Record honest outcomes and remaining limitations in validation.md.
