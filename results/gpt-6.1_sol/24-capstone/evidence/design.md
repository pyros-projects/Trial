# Afterimage design

The brief asks for a complete, distinctive, offline application chosen and implemented autonomously. The user explicitly asks for a single end-to-end run and says not to stop after ideas or a proposal; intermediate approval handoffs in general skills are superseded by that instruction. This new application is architectural work. The working directory is empty except for supplied skills and is not a git repository; implement in the required directory without a new worktree.

**Experience.** Afterimage is a tactile workshop about retaining information. Start with an original moth pixel memory encoded with eight extra symbols per band and a woven arrangement. Give a short integrated invitation to scratch, then recover. A second experiment compares the same horizontal fold in Rows and Woven layouts. Compose mode supports eight inks, drag painting, blank paper, editable examples, and a small embedded uppercase bitmap font. There is no audio.

**Visual identity.** Warm archival paper, deep evergreen ink, vermilion marks, generous serif headings, restrained monospaced annotations. A large coded mosaic is the working surface; the source and decoded result appear beside it. Use original Canvas drawing and inline SVG icons. Desktop has a surface plus control rail. Narrow screens put the controls and previews into the document flow with large touch targets and a full-width canvas.

**Codec.** 576 image bytes form 24 bands of 24 data bytes. For each band, systematic Reed–Solomon encoding evaluates a degree <24 polynomial at 24+p distinct nonzero GF(256) points (primitive polynomial 0x11D). Lagrange weights encode parity. The decoder interpolates from any 24 surviving values. It takes only a nullable received array and p. For insufficient bands, preserve surviving original data pixels and mark missing pixels unknown. Recoverable bands rebuild their entire codeword. Woven layout maps physical row/column to a transpose of the logical byte stream; Rows preserves sequential codewords. With eight extra pieces, a four-row physical fold destroys four entire bands in Rows and spreads five or six erased symbols per band in Woven.

**State.** All state lives in memory: pixels, title, p, arrangement, erased logical positions, tool sizes, mode, deterministic rain seed, result. Source edits and setting changes re-store the drawing and clear damage, with a visible explanation. Each pointer stroke is one history transaction. Recovery is synchronous and bounded to 24 short codewords. Undo/redo snapshots contain only session state; derived encoding/result recompute as needed. Whole-session Reset restores the original seed, clears both history stacks, terminates active strokes, closes dialogs, and increments import generations. No persistent storage or network access.

**Files.** `index.html` is the delivered complete runtime. `evidence/` contains research, design, plan, authored tests, browser logs, screenshots, and validation. Any development scripts are evidence only, never imported by the HTML.

**Portability.** Ordinary file input for imports; data-URL downloads for JSON and PNG. Validate size, schema, exact array length, palette bounds, p and layout, and duplicate/out-of-range erased indices before committing. Ignore stale async file reads after reset or newer actions. Use defensive feature checks for pointer capture and high-DPI canvas resizing. Avoid cookies, localStorage, IndexedDB, service workers, fetches, imports, and external assets. About links are optional and URLs are visible/selectable.

**Verification.** First run independently authored codec tests that fail when there is no codec, then implement and pass them. Validate genuine pointer and keyboard actions with agent-browser 0.31.1, at 1280×800 and 390×844. Test editable non-preset content, rain, arbitrary scratch, fold comparison, exact loss boundaries, partial/all loss, undo/redo, import/export, invalid import, reset and reload. Test direct `file://` and opaque-origin sandbox iframe with internet blocked. Inspect screenshots, actual live state, console, errors, failed requests, focus loss, and canceled pointers. Report unavailable checks honestly.
