# Atmospheric solver review

Scope: entire net-new `evidence/model.js`, checked against `evidence/model-brief.md`. Existing verification was read from `evidence/model-tests.cjs` and `evidence/model-report.md`; the 14-check suite was not rerun. Two small, independent probes covered gaps in those checks. No implementation changes were made.

## Findings

1. **P2 — Rain never replenishes soil on raised land** (`model.js:162`, with `model.js:131` and `model.js:153–157`). Soil replenishment reads `this.r[j]`, the absolute-altitude bottom voxel. Every column with positive terrain height marks that voxel as underground and zeros its rain before sedimentation. Actual ground rainfall is collected at the first voxel above terrain, but its flux is not used for soil moisture. Consequently every original land column only dries, even during heavy surface rain; this breaks the advertised precipitation/surface-moisture coupling. Use the per-column precipitation flux already calculated at the terrain boundary to replenish that column's moisture, with documented units. A controlled probe with terrain=1, initial soil moisture=0.5, evaporation=0, and 10 g/kg rain in the first atmospheric layer produced 0.0188903 mm ground precipitation in 0.25 seconds while soil moisture remained exactly 0.5. Add a regression comparing rainy and dry twins on elevated terrain.

2. **P2 — State validation accepts a non-string preset** (`model.js:220`; same permissive membership check at `model.js:24`). `Object.hasOwn(ATMOSPHERE_PRESETS,state.preset)` coerces the key to a string. Thus a JSON state with `preset: ["supercell"]` passes full validation, retains the array as its preset, and advances successfully. The import contract explicitly requires rejecting bad types and preserving a valid preset identifier. Check `typeof state.preset === 'string'` before membership; apply the same requirement to the constructor. A targeted probe changed only this property in a legitimate serialized state and confirmed acceptance and subsequent stepping. Add this case to malformed-import checks.

## Specification verdict

**Changes requested for the two findings above.** The remainder substantially meets the requested educational-model contract: all eight fields use the specified typed-array layout; deterministic initialization, full-state restoration, and documented resampling are implemented; transport, diffusion, evaporation, phase transfers, latent heat, rain sedimentation, buoyancy, pressure response, rotation, terrain uplift and material-dependent sources are visibly coupled in the code. Bounds, parameter ranges, preset diversity and diagnostic meanings are documented. Dynamic CFL subdivision scans current velocities each integration and records the actual subdivision count. The supplied report records finite long stress and >1,000-second supercell behavior plus exact next-step roundtripping. Those results are existing evidence, not independently rerun results from this review.

The first-order transport, periodic horizontal boundaries, approximate saturation/pressure physics, safety clamps and coarse terrain mask are disclosed modeling limitations consistent with an educational simulation. No additional blocking issue was identified in state copying, buffer swapping, sedimentation donor order, or resize metadata preservation. Browser behavior and rendering were outside scope.

## Code-quality verdict

**Acceptable structure after the fixes, with maintainability reservations.** The class has a small, consistent integration API, no dependencies, validates state before replacement allocation, and avoids cached array-reference assumptions by documenting buffer swaps. Tests exercise actual behavioral coupling and deterministic persistence rather than mocks. The solver is unusually dense: many unrelated calculations share individual lines, making unit reasoning and boundary review harder. A later readability pass should split `_integrate` into clearly named physical stages or at least use one operation per line, and annotate the soil-reservoir conversion. This is a follow-up recommendation, not a requirement to restructure the implementation now.

## Scoped final re-review

The final `model.js`, the appended model report, the three added regression tests, and `logs/model-tests-final.log` were inspected. No tests were rerun and no implementation files were edited. This section supersedes the earlier changes-requested verdict.

- **Finding 1 resolved.** `model.js:166–171` now uses the outgoing precipitation flux at the first voxel above each terrain column, accumulates its rainfall in mm, and adds `groundRainMm/100` to that column's soil reservoir. `model.js:177` only applies land drying or water-surface replenishment afterward; the underground rain lookup has been removed. The added elevated-terrain wet/dry regression checks actual soil gain and its unit conversion. The supplied final log reports 0.018899995 mm rainfall, wet moisture 0.5001890063, and unchanged dry moisture 0.5.
- **Finding 2 resolved.** Both the constructor (`model.js:24`) and import (`model.js:235`) require primitive string preset values before dictionary membership. The added regression covers arrays, boxed strings, coercible objects, null, numbers, and the malformed JSON array case. The final log records it passing.
- **Retention tuning inspected; no introduced concrete defect found.** The supercell override remains inside valid parameter ranges (`model.js:13`). `_backgroundHumidity` (`model.js:48–52`) is deterministic and uses bounded spatial forcing; initialization and integration both call it (`model.js:82` and `model.js:132`). Surface evaporation diminishes as saturation is approached (`model.js:129–131`). These changes modify vapor sources and initial conditions without directly reinserting cloud during evolution or introducing unpersisted mutable state. The final log records 17 passing checks, including exact state restoration, long stress stability, and developed but partial supercell cover at 210, 420, 630 and 1,080 seconds. This is reviewed supplied test evidence, not an independent execution.

**Final specification verdict: approved within the atmospheric-model scope. Final code-quality verdict: acceptable; the previously noted readability follow-up remains optional.** No outstanding concrete correctness finding was identified in this scoped re-review. Rendering, browser integration, and operational forecasting validity remain outside this review.

## Condensation-threshold scoped re-review

Inspected only the final phase-change correction at `model.js:135–137`, its two regression tests, the appended model report, and `logs/model-tests-threshold-final.log`. No tests were rerun or implementation files edited.

**Approved; no concrete defect identified in this change.** Condensation begins when vapor exceeds saturation multiplied by the configured threshold, with a fixed 0.07 s⁻¹ exponential conversion rate. Transferred vapor is bounded by its available amount, enters cloud, and releases latent heat. When condensation is inactive, evaporation uses actual undersaturation rather than the formation threshold; therefore a threshold above 1 does not wrongly evaporate existing cloud in supersaturated air. Thresholds below 1 intentionally permit stylized sub-saturation cloud formation. The independent weak mixing loss remains distinct.

The supplied final log records 19 passing checks, including separate onset/latent-heating and evaporation regressions, finite extreme stress, deterministic restoration, and the unchanged default storm trajectory. The report records identical complete-state SHA-256 after 30 default steps before and after this correction. These are reviewed existing results, not independent executions. The earlier final approval and optional readability recommendation remain in effect.
