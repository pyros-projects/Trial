Plan, implement incrementally, execute, inspect, diagnose, and improve your work throughout development. No previous implementation is assumed. Use the installed browser automation skill `agent-browser` to validate your work. ## Application requirements

Create a polished, direct-manipulation 2D vector and layout editor inside one self-contained `index.html`. Embed all HTML, CSS, JavaScript, artwork, and example documents; use browser-native rendering and system fonts, with no backend, external libraries, frameworks, modules, network assets, or runtime build process. All visible artwork must come from the editable scene. Build a focused authoring tool, not an Illustrator/Figma compatibility layer: Boolean path operations, arbitrary SVG import, collaboration, plugins, multipage publishing, and animation are outside the required scope.

Open with an appealing, fully editable composition that combines vector shapes, a custom curve, and deliberate typography. Include a second distinct editable composition and a New blank document command. Work with one artboard at a time, configurable from 64 to 2048 units per side, with a solid or transparent background. One document unit equals one output pixel at 1x. Templates must use the same scene objects and editing operations as user-created documents, not a flattened image or hidden special-case renderer.

### Editing core and geometry

Provide a zoomable, pannable workspace with direct selection, marquee and additive multi-selection, drag handles, numeric properties, duplicate, delete, a hierarchical Layers panel, and clear tool modes. Include rectangles, ellipses, lines, plain multiline text, and open or closed cubic Bézier paths. The path tool must create real anchors and handles; a node tool and numeric point controls must edit existing anchor/control coordinates, including within a transformed group. Allow opening and closing a path, with fill and stroke updating accordingly. Provide fill, stroke color/width, and opacity for appropriate items. Clipping masks, path Boolean operations, text outlines, and arbitrary freehand simplification are not required.

Keep the core finite: support at least 200 total scene items, up to 32 anchors per path, four nested group levels, and 2000 characters per text item. State any higher supported limits. Reject operations and imports that exceed the implemented limits before changing the document. Coordinates and transform values must be finite and bounded; reject singular transforms and zero or negative scale with useful feedback.

Separate document coordinates from viewport pan/zoom. Translation, rotation, and positive uniform scaling must work for objects, groups, and multi-selections. Rotate and uniformly scale around the selection's current document-space bounding-box center. Individual rectangles and ellipses may also change local width and height independently; group and multi-selection resize must be uniform so descendants retain their relative geometry and proportions. Skew and reflection are not required. When an ancestor and its descendant are selected together, apply an operation once to the ancestor, not twice to the descendant. Pointer coordinates and node edits must account for the complete parent transform and viewport transform.

Use a consistent, visible layout-bounds convention. Each leaf has a local geometry box: the explicit rectangle/ellipse box, line endpoints, actual cubic-curve extrema, or the text's typographic layout box. Curve bounds must follow the curve within 0.5 document units, not the remote control handles. A text box must use declared font metrics, line advance, and line height consistently; its bounds need not equal the exact ink outline of glyphs. Transform the corners of each leaf's local box into document space and take their axis-aligned bounds; group bounds are the union of descendant boxes. This deliberately defines conservative bounds for some rotated curves and ellipses. Exclude strokes, control handles, selection adornments, and viewport zoom from these bounds. Visibility does not erase stored geometry. Show the resulting document-space x, y, width, and height in the inspector so layout operations are inspectable.

Grouping requires a contiguous block of siblings with the same parent. Insert the new group at that block's position and preserve child order and all world geometry. Refuse grouping noncontiguous siblings or objects from different parents instead of silently changing occlusion. Ungroup by replacing the group with its ordered children and composing their transforms into the parent space; it must not change world geometry or paint order, even after group translation, rotation, and scaling. Support selecting a group as a unit and selecting its children through Layers. Grouping and ungrouping must remain reversible.

Layers must show the actual hierarchy and front-to-back paint order, with rename, sibling reorder, visibility, and lock controls. Ancestor visibility and locks apply to descendants. Hidden items do not render, export, or participate in canvas hit testing, but remain in the project. Locked items remain visible and exportable. Any operation that would alter a locked item, directly or through a parent, must refuse or be disabled without partial edits; users must still be able to unlock it through Layers.

### Layout, text, and history

Provide separate grid and object/artboard snapping toggles, visible snap guides, and a configurable grid with a 10-unit default. During pointer movement, compare the moving selection's bounding-box edges and centers with the artboard and visible unselected objects outside the moving subtree, excluding every ancestor of a selected object, and with the grid when enabled. Snap each axis to the nearest eligible target within 6 CSS pixels of the unsnapped pointer-derived placement, independent of zoom. Break equal-distance ties by the lower target coordinate, then the lower moving-feature coordinate. Hidden objects are not targets; visible locked objects may be targets. Numeric edits and keyboard nudges must remain exact rather than being unexpectedly resnapped.

Provide align left/center/right and top/middle/bottom relative to the selected items' union bounds. Equal-gap distribution for three or more items must keep the two outermost items fixed and place the others with equal gaps between their document-space bounds, without resizing or reordering layers. Sort by the leading bound on the chosen axis, using stable IDs to break ties. If the available span is smaller than the sum of the items' extents, refuse the distribution and explain why instead of introducing an undefined overlap rule.

Text must remain editable plain text. Support at least system sans-serif, serif, and monospace families, font size, normal/bold weight, left/center/right alignment, line height, explicit line breaks, and fill. Automatic word wrapping and rich-text runs are not required. Use the same text layout and line placement for editing, bounds, preview, and export. Treat every entered or imported string as data: markup-like text must never create HTML/SVG elements or execute code. While a text or numeric field is active, typing and its native editing shortcuts must not accidentally move or delete scene items. Enter or a clear commit action finishes an edit; Escape restores the pre-edit value.

Provide undo and redo for document edits, including geometry, styles, text, hierarchy, order, visibility, and locks. One completed pointer drag or continuous property scrub must be one history step, not one step per event; a committed text edit is likewise one step. Undo/redo must restore the associated selection. Selection changes, panning, zooming, and tool changes do not consume document history. A new edit after undo clears the redo branch. Escape, pointer cancellation, or focus loss during a drag must cancel the uncommitted operation and restore its starting geometry without adding history. Validate numeric edits before committing them.

### Project files, preview, and export

Offer an unobstructed artboard preview and explicit project JSON, SVG, and PNG downloads derived from the current scene. Project JSON must preserve item IDs/types, geometry, style, text, parent hierarchy, order, transforms, locks, visibility, artboard settings, and any supported embedded raster data. Use a versioned, validated own-project schema; cap input bytes as well as object counts, depth, text, coordinates, and asset sizes. Reject malformed data, duplicate IDs, cycles, missing references, unsupported types/versions, unsafe resource references, and non-finite values before replacing the current document. Invalid imports must preserve the scene, selection, and undo history. A successful project import, New document, or composition load replaces the document and clears history, with that boundary explained in the UI.

Do not import arbitrary SVG, HTML, script, or externally referenced assets. Optional raster import may accept a bounded set of local PNG/JPEG/WebP files through a file input, provided both encoded bytes and decoded dimensions are checked, invalid files fail without document loss, and project/export assets are embedded rather than fetched. Do not add a required raster workflow merely to fill the toolbar.

SVG export must contain actual vector shapes/paths and safely escaped text from the current artboard, with correct transforms, paint order, fill, stroke, opacity, and background. Exclude hidden objects and editor UI. Generate a safe SVG subset with no script, event attributes, `foreignObject`, or external resource references; optional raster assets must be embedded data. PNG export must render that same artboard at selectable 1x and 2x resolution, with correct transparency and pixel dimensions, rather than capture the surrounding editor or reuse a preset thumbnail. Bound exports to at most 4096 pixels per side and 16,777,216 pixels total, report refused sizes, and preserve editing state on failure.

### Session behavior and usability

The complete workflow must function in an opaque-origin iframe with `sandbox="allow-scripts allow-downloads"`, without `allow-same-origin`. Do not require browser storage, cookies, clipboard permissions, filesystem APIs beyond file input/download, service workers, a backend, or any network request. Keep document and history in RAM; explicit project download/reimport is the persistence mechanism. Reloading or reopening starts from the same initial composition. A clearly visible Reset command must restore that composition and clear selection, history, imported assets, transient UI, pending file operations, and application timers that could reapply stale state. Reset is a documented, non-undoable fresh-session boundary.

Give the editor a deliberate visual identity: crisp handles and paths, readable typography, restrained panels, discoverable shortcuts, visible focus, and understandable selected/locked/invalid states. Keep mouse and touch/pointer editing usable at desktop and narrow widths, with accessible labeled controls and workable panels. Handle high-DPI displays, pointer cancellation, viewport resizing, and bounded scenes without losing selection or detaching handles from their objects. Show compact, truthful diagnostics for active tool, zoom, selection, bounds, item/anchor counts, history availability, and import/export status. Treat geometry correctness, direct editing, typography, coherent history, safe round trips, export fidelity, visual quality, and robustness as benchmark criteria.

# Public validation checks: Vector & Layout Studio

Perform these checks against the actual application using labeled controls, pointer gestures, keyboard input, and the files it really downloads. Inspector values, parsed project JSON, and live geometry diagnostics may corroborate an interaction; invoking internal mutation functions is not a substitute for doing it. Record observed outcomes and failed attempts. Do not hard-code these sequences or treat an attractive screenshot as proof of correct editing.

1. **Editable opening and offline delivery.** Open the default composition, select its shapes and text, and change both. Load the second composition and inspect its editable objects. Test direct-file opening and an opaque-origin iframe with `sandbox="allow-scripts allow-downloads"`, without `allow-same-origin`, external resources, or storage access. The editor must start and remain usable. Record blocked environmental checks honestly.

2. **Creation and coordinate continuity.** Create rectangles, an ellipse, a line, and text with the actual tools. Move and resize objects with handles, then refine values in the inspector. Pan and zoom, resize the browser, and drag again: the object must track the pointer without a jump or an accidental second transform. Check the document-space bounds against the visible geometry at both 1280 x 800 and 390 x 844. Exercise multi-selection, duplicate, delete, and keyboard movement without deleting an object while typing into a field.

3. **Snapping.** With grid snapping off and object snapping on, move an object's edge toward another visible object's edge at 100% and 200% zoom. A proposed position within 5 CSS pixels must snap and show the relevant guide; a position 8 CSS pixels away from every eligible target must not. Verify the final document coordinate, not only the guide. Then check grid snapping separately and ensure hidden objects and objects inside the moving selection do not attract the selection. Select a nested child through Layers and drag it: its ancestor groups must not act as snap targets; a nearby eligible sibling or external object still can.

4. **Alignment and equal gaps.** On a blank 1200 x 800 artboard, create three unrotated rectangles with bounds A=(40,60,80,40), B=(180,100,60,40), and C=(320,160,80,40), expressed as x,y,width,height in document units. Select all and align their top edges: every y must become 60. Distribute horizontally: A and C stay fixed, B moves to x=190, and both gaps become 70. Confirm that sizes and stacking order stay unchanged. An impossible equal-gap distribution must report why and leave the scene unchanged.

5. **Groups and transforms.** Group two contiguous sibling objects and confirm their world positions and paint order do not change. Translate, rotate, and uniformly scale the group through the controls; descendants must move together without drift. Record their world geometry, ungroup, and compare it within 0.5 document units, including a rotated child. Exercise a nested group and undo/redo around group and ungroup. Attempt grouping noncontiguous siblings or objects from different parents and verify a clear refusal without changing geometry, order, or selection. A selected ancestor and descendant must never receive the same transform twice.

6. **Actual curve editing and bounds.** Draw an open cubic path using the path tool and manipulate its anchors and handles. Use the numeric point controls to set endpoints (100,100) and (200,100), with outgoing/incoming controls (100,0) and (200,0). Its unrotated layout bounds must be approximately (100,25,100,75), within 0.5 document units, excluding stroke and handles. Move a control point and observe the curve and bounds change. Create and reopen a closed filled path, and edit a node after rotating or grouping the path. Confirm export retains its editable cubic geometry.

7. **Text and typography.** Edit multiline text, font family, size, weight, alignment, line height, and fill. Enter literal text such as `<img src=x onerror=alert(1)> & "layout"`; it must remain text in the editor, project JSON, and exported SVG, with no injected element, alert, or resource request. Confirm the displayed layout box and export agree after changing line breaks and rotating the text. Commit a text edit, undo it in one document-history step, and cancel another edit without changing the document.

8. **Layer order, visibility, and locks.** Overlap colored objects and reorder them through Layers; the occlusion in both the editor and export must follow that order. Hide an item, show it again, and verify it was not deleted. Lock an item and attempt canvas dragging, deletion, and a parent-group transform that would move it. Each must leave it unchanged and give understandable feedback. Unlock it and repeat the intended edit. Hidden items must not be hit-test targets; locked visible items must still export.

9. **Coherent history and cancellation.** Make one long drag, one slider scrub, a committed text edit, and a layer reorder. Undo and redo each completed operation as one unit, checking geometry, styles, hierarchy, and selection. Pan, zoom, and change selection between undo steps without consuming document history. Undo an edit, make a different edit, and confirm the old redo branch is gone. Cancel an in-progress drag with Escape and a pointer-cancel/focus-loss case; no partial geometry or extra history entry may remain.

10. **Project round trip and hostile inputs.** Download a project containing paths, styled text, nested transforms, hidden items, and locks. Change the document, reimport the downloaded file, and compare the scene and hierarchy. Mutate copies of that actual format to include malformed JSON, a duplicate ID, a cyclic parent relationship if the format uses references (otherwise excessive nesting), a non-finite number such as `1e309`, an unsupported item type, and a count or size beyond the stated limits. Reject each without losing the current document, selection, or undo history. Reject arbitrary SVG/HTML imports and remote resource URLs without fetching or executing them. If raster import is implemented, also test a valid local raster, a disguised non-image, and an image beyond its declared byte or decoded-pixel limits.

11. **Scene-derived preview and exports.** Change a shape, a Bézier handle, a text string, visibility, and layer order before exporting SVG and PNG. Open the downloaded files and inspect both their contents and rendering: they must show those changes, the artboard dimensions and background, and no editor handles or guides. Check PNG pixel dimensions at 1x and 2x, and check that the SVG contains vector geometry and safely escaped text rather than a screenshot of the workspace. Verify that controls prevent an oversized export or refuse it clearly without changing the document. Verify exported SVG has no script, event handlers, `foreignObject`, or external resource references.

12. **Session boundary and reset.** Modify a composition, import a project, and leave an edit or optional raster decode pending before using the visible Reset command. Reset must restore the initial composition and clear selection, history, transient UI, pending operations, and imported assets; no delayed callback may restore old content. Reload and reopen the delivered HTML and verify the same fresh start. Explicit project download/reimport must work with persistent browser storage unavailable. Record console errors, failed requests, and any remaining input or export limitations.
